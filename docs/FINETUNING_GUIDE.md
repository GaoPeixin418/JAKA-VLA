## 当前技术路线的准确定位

当前基础策略路线是：**预训练 SmolVLA → 使用两台 Zu7 的仿真专家示教进行监督式模仿学习微调 → 在仿真中闭环执行和评价**。

论文原定研究问题是在双臂协作关键事件附近调整重规划时机。SmolVLA微调是建立基础策略的步骤；学习式事件监测器、自适应K、延迟实验和真机迁移尚未实现。目前基础策略尚未通过已见场景验收，不能报告成完整研究方法已完成。

## 选用的微调方法

采用**冻结视觉语言主干、训练动作专家及相关投影层的部分参数微调**，训练目标是SmolVLA自带的条件流匹配（flow matching）。这是使用专家动作监督的模仿学习。

| 项目 | 实际设置 |
| --- | --- |
| 基座 | `lerobot/smolvla_base`，权重固定版本 `5e8d12a6e2975b0e5e5fce7c8caf47c371d257b6` |
| 视觉语言主干 | `HuggingFaceTB/SmolVLM2-500M-Video-Instruct`，当前保留16层VLM |
| 总参数 | 450,046,176，约450M |
| 可训练参数 | 99,880,992，约99.88M，占约22.2% |
| 冻结 | 视觉编码器和整个VLM主干，`freeze_vision_encoder=true`、`train_expert_only=true` |
| 更新 | 动作专家、状态投影、动作输入/输出投影、动作时间相关MLP；专家中不使用的lm_head按上游实现冻结 |
| 状态投影 | `train_state_proj=true` |
| PEFT | `peft=null`，本轮没有使用LoRA/QLoRA或低秩适配器 |
| 强化学习 | 没有用奖励训练、PPO或在线RL；也未开启RA-BC |

因此，“微调约100M动作相关参数”是准确表述；不是450M全部参数更新，也不是只训练一个很小的最后输出层。没有为此次工作发明新的微调损失。

## 网络到底学什么

一次训练样本由当前观测和未来专家动作块构成：

```text
输入：当前头部RGB + 左腕RGB + 右腕RGB
      当前实测14维关节/夹爪状态
      本任务的自然语言指令
监督：未来50步的14维专家指令目标
```

状态/动作顺序都是：`[左臂6关节, 左夹爪开度, 右臂6关节, 右夹爪开度]`。关节用弧度，夹爪开度归一化到[0,1]。动作是绝对关节位置目标和夹爪开度目标，不是力矩，也没有开启ALOHA专用delta动作变换。

- `state(t)`读取真实仿真qpos和夹爪实际开度，不能用控制器指令冒充测量。
- `action(t)`标签是下一采样点的指令目标，即约`command(t+0.04s)`。模型从这个标签起预测未来50步。
- 原始RGB为320×240；训练特征声明`[3,240,320]`，模型内部按配置缩放/填充到512×512。两者是不同处理阶段。
- 状态和动作使用当前数据集均值/标准差归一化，模型内部填充到最大32维，最终还原为14维控制输出。
- 25Hz下50步是2秒预测范围；评测K=8代表只执行前8步、约0.32秒后重新观察。H与K不是同一个参数。

流匹配训练在标准化专家动作块A与随机高斯噪声ε之间采样中间状态：

```text
x_t = t × ε + (1 − t) × A
目标方向 u_t = ε − A
损失 = 预测方向与 u_t 的均方误差（按上游掩码/归约规则处理）
```

模型结合图像、指令和关节状态，学习如何把噪声逐步变为合理动作块。推理采用10个积分/去噪步骤；“10步生成过程”也不等于机器人执行K。最终训练loss是流匹配损失，既不是抓取成功率，也不是以厘米表示的末端误差。

## 任务是如何设计和采集的

任务固定为左臂抓住红色长方块、抬升、送到交接区，右臂接住后左臂释放并退回，右臂把方块放到蓝色接收台上并松开。

用官方Zu7的URDF与网格建立两台6关节机械臂；暂定10cm开口平行夹爪、15cm TCP偏置、基座间距0.85m。因Zu7腕部较大，蓝色接收台改为8cm高。夹爪型号、安装和动力学尚未按真机标定。

数据来自RoboTwin/SAPIEN内的脚本专家：脚本指定任务阶段/接触点，cuRobo求关节路径，仿真执行并记录三相机RGB与测量/指令。它不是人工遥操作数据，也不是通过模型自己试错获得的成功经验。

物理仿真250Hz，每10物理步统一采样，得到25Hz数据；跨动作阶段保持同一采样时钟。随机种子改变方块初始位置/朝向和目标位置。示教有几种同义英文任务指令，但都描述同一个任务，不能因此声称多任务或语言泛化。

本轮保持背景/光照等域随机化关闭，训练图像增强也关闭，先排查控制和拟合。采集每批目标3条成功示教、最多尝试12个种子，失败日志保留。

两个正式Zu7批次：

| 数据集 | 轨迹与帧 | 内容 |
| --- | --- | --- |
| `data/lerobot/zu7_smoke` | 3条、1232帧 | 第一版完整交接示教，后来发现接近阶段存在双臂碰撞 |
| `data/lerobot/zu7_collision_smoke` | 3条、1296帧 | 专家规划加入对方机械臂几何，末段退回/放置串行，重新采集 |

两批都使用seeds0、1、2，因此是同3个初始场景的两版轨迹，不是6个独立场景。新批次替换第二阶段训练源，没有把两批与旧ALOHA数据混在一起。当前训练只用成功示教，失败轨迹尚未做恢复动作标签并加入训练。

## 数据落盘和转换

第一层为原始HDF5，每回合保留RGB编码、测量状态、动作、时间戳、TCP等。另存`commanded_state`便于排查跟踪误差。每个批次有`robot_identity.json`，HDF5标注机器人和URDF哈希。

第二层为LeRobot v3：

```text
data/lerobot/zu7_collision_smoke/
  data/chunk-000/file-000.parquet       # 数值状态、动作、时间和索引
  videos/observation.images.camera1/   # 头部相机MP4
  videos/observation.images.camera2/   # 左腕相机MP4
  videos/observation.images.camera3/   # 右腕相机MP4
  meta/info.json                      # 维数、帧数、相机格式、机器人类型
  meta/stats.json                     # 归一化统计
  meta/tasks.parquet                  # 语言指令
  meta/episodes/                      # 每回合索引信息
  meta/project_identity.json          # 机器人、几何和采样语义
```

转换检查：实测状态语义、14维、有限值、0.04秒均匀时间戳、动作下一时刻对齐、RGB格式、URDF/机器人身份。RGB解码由XPolicyLab共享工具完成。

## 实际做了哪几次训练

| 阶段 | 起始权重 | 训练数据 | 优化器更新数 | 含加载/保存耗时 | 闭环结果 |
| --- | --- | --- | --- | --- | --- |
| 历史ALOHA pilot | SmolVLA基座 | 50条、18744帧 | 2000 | 449.3s | K4/8/16共0/9 |
| Zu7阶段1 | SmolVLA基座 | zu7_smoke：3条、1232帧 | 3000 | 645.4s | 已见seeds0–2，K8，0/3 |
| Zu7阶段2 | 阶段1的Zu7检查点 | zu7_collision_smoke：3条、1296帧 | 额外3000 | 653.1s | 已见seeds0–2，K8，0/3 |

历史还保留20步的环境/显存检查和旧状态语义的smoke检查点；这些是工程排错产物，不是额外的有效Zu7训练。Zu7训练并未从ALOHA微调权重继续；第一阶段从公开基座开始。

两次Zu7训练共同配置：batch8、seed42、AdamW、峰值学习率1e-4、warmup200步、余弦衰减到2.5e-6、梯度裁剪10、AMP、4个数据worker。WandB和Hub上传关闭。

每3000次更新抽取约24000个观测起点/动作块，相当于约19.48或18.52个数据遍历量。它不等于24000条示教，也不代表增加了独立场景。

第二阶段加载第一阶段模型权重，但重新计算新数据归一化统计，重建优化器和学习率调度；`resume=false`。因此是连续两阶段微调，而非保留优化器状态的6000步单次训练。第二阶段目录中的`003000`是该阶段3000步，累计才是6000步。

两阶段峰值分配显存均3.575GiB、预留3.660GiB；这是PyTorch分配器统计，不是整卡所有进程占用。日志最后一段流匹配loss分别约0.009、0.007，闭环仍0/3，说明训练损失很低也不保证执行成功。

训练配置内`eval.n_episodes=50`是模板残留的默认字段，但`env=null`、`eval_freq=0`，实际没有自动运行50回合评测。真正评测由项目脚本另行运行，每组3个回合。

## 微调之外刚刚做了什么

除了训练，还修正工具子link/TCP坐标、世界桌面到两臂基座的变换、夹爪碰撞模型，并增加另一臂几何约束。控制器增加同一未来时刻的动作块衔接、位置/速度一致输出和指令速度/加速度限制。

新增基于指令与实测反馈的空抓检测、持续跟踪异常检测；检测失败后结束仿真回合。它们不是已训练的事件监测器，也没有自动重新抓取。接触冲量和物体位置只用于诊断/评价。

修正后专家回放3/3完成稳定放置，但两条仍有短暂指/掌接触。模型最终默认采样0/3，额外零噪声诊断也0/3；后者没有再训练。主要表现为两次左空抓，一次抬起后跟踪异常。未扩展未见场景测试。


其中`model.safetensors`约906.7MB（约864.7MiB），包含完整策略权重，并非LoRA适配器小文件。必须同时保留`config.json`、`train_config.json`、`project_identity.json`、`policy_preprocessor.json`、`policy_postprocessor.json`及两份normalizer/unnormalizer safetensors；只拿权重而丢掉归一化统计不能等价复现。

相邻`training_state/`内还有AdamW状态（约412.7MB）、参数组、scheduler、随机数状态和训练步数，供真正续训。`last`是指向`003000`的相对软链接。

## 下一步的优先级

当前先解决接近抓取阶段的预测对准、数据覆盖和双臂运动裕量，增加有标签的失败/恢复示教。之后再验收独立场景，建立可靠固定K基线，最后研究事件触发重规划。换LoRA、增训练步数或降低采样随机性，都不能替代这些闭环验收。
