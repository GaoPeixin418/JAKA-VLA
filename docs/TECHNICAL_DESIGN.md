# 技术方案与决策记录

更新日期：2026-11-06。用户确认两台 Zu7 并授权暂定夹爪/安装。当前进行 Zu7 仿真接入、控制修正和基础策略重新验收；事件自适应重规划及真机迁移仍是后续工作。

## 研究问题

双臂交接中，接近、夹持转换、释放等阶段对重新观察的需求不同。研究假设是：在同等计算预算下，根据可观测的协作事件/执行风险调整重规划时机，可以改善成功率和反应速度。该假设尚未得到实验验证。

模型预测动作块长度 H=50，控制频率 25 Hz，完整块对应 2 秒；执行 K=4/8/16 分别为 0.16/0.32/0.64 秒后再观察。K 不是预测长度，也不是墙钟推理时间。

## 当前系统

## 数据与控制接口

- 物理步长约 0.004 秒，观测/动作间隔约 0.04 秒；采样跨专家运动 primitive 连续进行。
- 状态顺序 `[左臂6关节, 左夹爪, 右臂6关节, 右夹爪]`，关节为弧度，夹爪归一化至 `[0,1]`。
- `state(t)` 来自实际关节 qpos 与实际夹爪开度；`action(t)` 为下一采样时刻的驱动目标 `command(t+0.04s)`。
- 原始数据另存 `commanded_state(t)`，用于与实测位置比较；不能将它替换成策略状态。
- HDF5 标记 `state_semantics=measured_qpos`、`action_semantics=next_sample_drive_targets`，保存 observation/action timestamps。
- 转换通过 XPolicyLab 共享 loader、动作维数与 pack 工具处理。RGB 不自行交换通道；检查 dtype/维数/样本数/有限值及时间间隔。
- 相机映射：`cam_head→camera1`，`cam_left_wrist→camera2`，`cam_right_wrist→camera3`。
- 新控制器在250 Hz物理步上过滤目标，限制指令速度/加速度，并同步设置位置与速度目标。指令限速不等于物理关节速度保证；每步记录实际qpos/qvel用于验证。
- 重规划时只融合指向同一未来时间的前4步关节目标，夹爪不跨块平均。固定初始噪声是显式可切换实验设置，不代表提升了预测精度。
- 新增空抓监测：闭合请求<15%且实测开度<8%持续0.16秒，判为空抓并结束该回合。只用本体感知；阈值仅适配当前10 cm开口代理夹爪与6 cm方块，不能证明任意非空开度都抓到了物体。自动重新抓取尚未实现。
- 学习评测成功需满足原任务位置容差、右夹爪实测开度>85%、物体速度<0.02 m/s持续0.4秒。物体真值只用于评价，不送入策略/空抓监测器。

## 已作出的关键决策

| 决策 | 观察到的问题 | 处理与验证 |
| --- | --- | --- |
| D01 环境隔离 | 仿真依赖 NumPy1，模型栈需要 NumPy2 | 两个 Python 环境，socket 传观测/动作；依赖检查、短闭环通过 |
| D02 均匀时间采样 | 原 save_freq 是物理步间隔，且 primitive 边界采样不均匀 | 统一计数每10物理步采样，视频25FPS；转换检查时间戳 |

| D04 先校验控制链路 | 学习失败可能来自控制或归一化错误 | 完成检查点重载与专家回放，再跑完整学习评测 |
| D05 先固定 K | 需要基础策略与可比较参照 | 同一权重、控制器和测试种子；先不加入事件模块 |
| D06 两种时间分开 | 同步推理时仿真暂停 | 单独记录 sim_seconds、wall_seconds 和 inference_seconds；不声称抗延迟 |

## 评测定义和下一阶段设计

当前Zu7学习评测包装器默认每回合最多650控制步，即26秒仿真时间；实际命令可显式覆盖，旧ALOHA pilot为750步。成功判据在任务 `check_success()` 之上要求实测释放和稳定放置。记录成功、控制步数、模拟/墙钟时间、策略调用数、逐次推理耗时及视频。
现有 pilot 只有训练 seed42 与 3 个测试种子；后续报告必须增加独立训练种子、测试回合和不确定性估计。

拟开发的事件模块优先关注夹持转换、接近交接点、执行误差升高。输入候选为可部署视觉特征、关节/夹爪状态、最近动作及其残差；暂不假定真机已有力传感器。
仿真接触和物体真值可帮助生成事件监督，但推理输入不得依赖这些真值。正式训练前必须明确事件标注和失败样本来源。

动作队列与延迟实验需要明确：观测采样时刻、推理开始/结束、动作目标对应时刻、队列耗尽处理、重规划替换规则、仿真在推理期间的推进方式。不能简单把墙钟推理耗时加到总用时就声称实现了延迟控制。

对照候选：固定 K、规则事件触发、阶段触发、学习监测器，以及监测器输入/阈值消融。比较时计入策略和监测器的总计算时间，并同时展示成功率与开销；可另报告相同平均调用预算的结果。所有这些对照当前尚未实现。

## Zu7 适配决策与验收

- 来源：JakaCobot/jaka_ros2，固定提交 `7e985b78fe3c7807507fb81e8119b76f794e3bae`。保留6关节运动学/网格，工具为可替换平行夹爪代理。上游package.xml许可写TODO；网格只本地下载，不包含在交付代码压缩包。
- 参考安装：基座间距0.85m，世界y=-0.42m、z=0.86m，同向绕z旋转90°，桌面z=0.74m。固定基座支撑被简化，须按真机重新标定。
- 工具TCP沿工具+x，偏置0.15m；暂定夹爪最大开口0.10m。原URDF惯量/质量直接继承，并非经过实物验证的动力学。
- 修正末端坐标：SAPIEN固定关节global_pose与工具子link姿态相差180°，Zu7显式使用子link姿态计算TCP；保留历史机器人的原有约定。
- 修正桌面坐标：顶面0.74m、厚0.05m，对应碰撞盒中心0.715m；每臂将同一世界桌面转换到自身基座坐标系。
- 夹爪掌部用小体素外接球覆盖真实碰撞盒，替代半径0.065m的过大单球。碰撞检查没有整体关闭。
- 原地面接收垫不适合此接取姿态的腕部净空；上移右抓取点又造成双臂物理相碰。最终场景采用8cm高的蓝色接收台座，保留上下抓点±7cm与原任务目标关系。
- 初版专家3/3成功，但限速回放0/3：专家峰值2.67rad/s超过控制器1.5rad/s，改变了到位/夹爪时序。尝试专家velocity_scale=0.35后在12个种子均未通过接近/规划验收，停止该方案并保留失败记录。最终采用低于URDF 3.14rad/s的3rad/s仿真指令上限，匹配原专家速度范围，回放3/3成功。它仍不是经真机确认的参数。
- 训练特征由数据集明确生成：STATE14、ACTION14、RGB `[3,240,320]`；不再继承基座模型的STATE6和256×256声明。

## 2026-11-05旧 ALOHA 失败诊断（历史）

本轮基础策略0/9，不适合作为事件方法的有效性能基线。离线诊断发现动作随机性、训练来源观测预测误差和跨块目标跳变；详见 `DIAGNOSIS_20261105.md`。
当前控制器没有跨块融合或速度/加速度限制；专家采集使用位置/速度轨迹，评测关节速度目标为0，存在控制差异。当前仅有一条专家回放验收，尚不能排除控制问题。
保存配置的状态维数仍为6、图像声明256×256，与实际14维/240×320不符。实测状态完整进入32维padding，归一化正常，因此不能认为已截掉右臂；但后续实现需要修正元数据并加入严格断言。
以上为修正前的历史诊断记录；当时尚未改变模型、数据或控制器。正式增加训练和事件方法前，先补轨迹记录、多案例控制验收与少轨迹抓取学习验收。

## 双臂碰撞补充修正

接触日志确认旧独立规划方案中右工具/手指撞左Link_2。每次专家规划现以另一臂当前网格和工具盒更新世界碰撞模型；末段动作串行化以保持另一臂静止。seed0新专家探测无双臂接触。
新3条示教1296帧，回放3/3成功；seed0无交叉接触，seed1/2仍有右指/左掌的轻碰，峰值约3.9Ns。实测速度峰值降为2.665/3.924/2.499rad/s。规划修正有效缓解严重碰撞，但尚不保证执行轨迹零接触。
学习策略直接输出动作，不调用专家规划器；不能给它继承专家的碰撞保证。新增持续跟踪异常终止检查（>0.12rad持续0.04s）只读可部署的关节反馈，并非自动恢复方法。
