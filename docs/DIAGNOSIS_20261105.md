# 首轮模型失败与抖动诊断报告

日期：2026-11-05，北京时间。针对用户观察到的无目标运动、未抓取即进入交接动作、推倒方块和普遍抖动，检查现有代码、配置、数据及录像，并对已有检查点做有界离线诊断。未重训，未修改原模型或执行控制器，未增加闭环评测回合。

## 判断与证据范围

当前基础策略没有达到可用水平，不能据此开展事件重规划方法效果比较。完整pilot为K4/K8/K16各0/3，总计0/9。
已确认模型在输入不变时仍产生较大的动作目标变化，且在抽查的训练示教观测上存在关节与夹爪预测误差。当前控制器缺少动作连续性约束，并与采集专家使用的控制方式不同。这些是优先排查因素；尚无逐物理步闭环轨迹，不能量化各因素对视频抖动的贡献。
“未理解任务”是行为描述，不是已经被实验定位的内部原因。当前只训练一个任务语义，没有做语言条件消融或场景改变测试，无法区分视觉定位、动作学习、语言使用和控制执行各自的问题。

## 为什么会抖：已确认的动作噪声与执行方式

SmolVLA以flow matching方式生成动作块。当前 `policy_server.py` 每回合设置一次随机种子，但每次predict仍重新采样噪声；同一回合可复现并不意味着每个动作块共享噪声或连续。
执行器直接丢弃旧块未执行部分，取新块前K步。没有跨块融合、沿用上一块作为初始化、速度/加速度限制或夹爪滞回。
关节仅做位置限位；每个40ms动作内做10个物理步的线性目标插值，所有关节速度目标设为0。位置插值不能保证相邻动作速度连续，更不能消除生成模型的高频目标变化。

离线诊断测得：

| 检查 | 结果 | 解释 |
| --- | --- | --- |
| 同一训练初始观测推理32次 | 左关节2首步目标标准差4.22°，右关节2为3.93° | 输入不变已有明显目标噪声 |
| 不同随机样本首步差 | 逐关节绝对差平均2.38°，95分位8.07°，最大17.21° | 均为预测目标差，不是测得的机械臂振幅 |
| 固定输入且固定种子重复 | 输出最大差0 | 本测试的变化来自随机采样，不是每次读取图像不同 |
| 同一块前16步相邻目标变化 | 逐关节绝对差平均1.30° | 抖动风险也存在于块内，不只是重新规划瞬间 |
| 专家观测序列上K4块边界 | 模型平均目标跳变2.56°，同位置专家0.47° | 在“正确观测”下，新旧动作块衔接仍不稳定 |
| 同样方法K8/K16 | 模型3.21°/3.66°，专家0.47°/0.45° | 小样本诊断，不能拿此数值直接排名K效果 |

例如0.14rad目标变化被安排在0.04秒内，所要求的平均目标变化率约3.5rad/s。实际关节是否达到该速度、是否发生跟踪滞后或接触振荡，必须补测qpos/qvel/驱动目标/接触。
此处没有新增仿真回合，块边界数据采用训练episode0的专家观测序列，而非原9段视频的逐帧控制记录。

## 为什么接近方块却抓不住

### 基础动作适配尚不充分

2000×8=16,000个观测起点，相对18,744帧约0.854遍。每个起点监督未来50步，不能解释成每个动作标签只见过0.85次；但视觉/状态观测起点覆盖与重复学习仍很有限。
学习率预设虽写warmup1000/decay30000，但运行代码自动缩放为warmup66/decay2000；所以“前半程都在warmup”不成立。训练终止时学习率已降至约2.7e-6。
最后训练loss=0.024是归一化空间的流匹配速度场损失，平均还包含补齐到32维的输出（实际14维）。它既不是弧度误差，也不是成功率，不能用来认定动作精度足够。

对4条训练轨迹的16个观测时刻，每个采样4次，共64个动作块：

- 首步关节目标平均绝对误差1.94°，95分位约6.78°；这是训练来源观测上的误差，闭环偏离示教后可能更差。
- 首步夹爪目标平均绝对误差0.097（量程0–1）；裁剪到0–1后仍为0.081。
- 例：episode49/frame250，专家左夹爪目标约0.99，模型均值约0.48；专家右夹爪目标0，模型约0.156。这说明即使输入专家画面，交接阶段夹爪时序也可能不对。该样本不是原测试视频，不能说它直接解释了某段测试的失败。
- 不能从关节误差直接换算实际末端偏差；需要机器人正运动学或末端轨迹。抓取属于接触任务，必须进一步核对末端位姿、指尖位置、闭合时机和物体抬升。

原始预测夹爪目标有45.4%略超出0–1，但只有约10.5%超界超过0.05、约2.0%超过0.1。许多边界轻微超界会被裁剪，不能仅用45.4%夸大问题；裁剪也不能纠正闭合时机。

### 专家控制与当前评测控制不完全一致

专家采集沿cuRobo轨迹执行位置与非零速度目标；当前评测用40ms位置线性插值、关节速度目标为0，绕过上游默认的TOPP时间参数化。
更换控制器的初衷是固定25Hz，明确K的时间含义；代价是引入了新的控制分布差异。当前机器人关节增益为stiffness1000、damping200，沿用资产配置，未做动力学标定。
一个专家seed0回放成功只能说明这一案例可执行，不能排除其他初始条件和带噪目标下的控制问题。
因此，不能断言抖动“全是模型问题”，也不能断言“调低PD就能解决”；应先用同一批专家目标比较控制器并记录实测轨迹。

## 为什么没有抓到还会出现交接动作

本轮只有完整成功示教，没有失败恢复数据；模型同时输出两臂动作，没有独立的抓取成功检测、物体持有状态、阶段门控或重试策略。输入只有当前时刻的三张图和关节/夹爪状态，`n_obs_steps=1`。
夹爪开度并不能单独证明抓住物体。初始抓取一旦失败，后续观测脱离成功示教分布，模型可能仍生成“像交接”的姿态。这是符合当前设计的失败机制假设；尚未通过阶段标注确认每个回合的具体转折。
脚本专家有抓取→抬升→交接→放置的程序逻辑，但训练策略没有自动继承专家状态机。它学习的是观测到动作的映射。

## 接口检查：发现的问题与没有发现的问题

发现一处实际配置缺陷：预训练配置保留 `observation.state.shape=[6]`、图像声明256×256，数据实际是14维、240×320。此前命令虽尝试传空input_features，但保存配置显示没有如预期替换；只检查输出14维不足以发现此问题。
进一步实测：输入状态14维，预处理后1×14，模型补齐为1×32，前14维全部保留；归一化与数据统计手算最大差约2.32e-7。因此当前未发生“只看左臂6维、丢掉右臂”的截断，不能把这个元数据错误定成失败唯一根因。它仍应在后续修改中明确修正并加入断言。

| 核查 | 结果 | 覆盖范围 |
| --- | --- | --- |
| action(t)与command(t+1) | 最大差0 | 全50条、所有非末尾相邻记录 |
| HDF5与LeRobot状态 | 最大差0 | episode0/frame0抽查 |
| 状态归一化 | 最大差约2.32e-7 | episode0/frame0、14维 |
| 动作反归一化零值对应数据均值 | 最大差约3.98e-8 | 14维处理器检查 |
| 图像RGB | 正常对应MAE约1.6–1.9/255，反转通道MAE约11.5–27.8/255 | 同一帧三路相机，差异包含视频压缩 |
| 训练/测试种子 | 训练范围0–55中50个成功种子；测试1000–1002无重叠 | 种子文件与评测配置 |

这些检查降低了明显通道颠倒、状态截断和一步错位的嫌疑；不等于已排除所有坐标、图像时间戳、接触或状态分布问题。

## 本轮实施与汇报不足

1. 没有在完整闭环评测前做动作误差、重复采样稳定性与单轨迹学习验收；工程验收不足以支持效果判断。
2. 自定义控制器只验证一条专家回放，没有多初始状态复核或逐步qpos/qvel日志。
3. 原评测只保存成功标记、耗时、调用次数和视频，没有保存预测动作、实际关节轨迹、末端/物体姿态、接触、夹持标记。因此不能现在从旧日志直接画出真实抖动曲线。
4. 保存配置的6维状态元数据未被及时发现；接口检查应覆盖输入语义和张量，而不只看输出形状。
5. 首轮2000步明确是有界pilot，但“训练完成”的汇报容易掩盖基础策略还未通过抓取验收。之后应按抓取、抬升、交接、放置分别报告。
6. 在用户指出问题前，未系统逐段分析失败录像；本次只对专家seed0和三种K的seed1000提取关键帧，不能冒称已逐帧分析9段视频。

## 建议下一轮修改的优先级（尚未执行）

| 优先级 | 修改/实验 | 要回答的问题 |
| --- | --- | --- |
| P0 | 修正14维输入声明、图像声明和运行时断言；补逐步日志 | 输入/输出到底是什么，抖动发生在预测、块切换还是物理跟踪 |
| P0 | 多条专家轨迹用统一控制器回放；比较位置/速度目标处理 | 控制链路是否在多初始条件下可靠 |
| P1 | 先固定初始条件做单轨迹/少轨迹学习和抓取抬升验收 | 模型能否学会最基本动作，再讨论泛化 |
| P1 | 按测量结果做跨块衔接、速率/加速度约束和夹爪策略对照 | 缓解噪声且不破坏抓取时机；不能只靠平滑掩盖目标错误 |
| P2 | 基础验收后再制定有界训练增量、定期闭环验证和最佳检查点选择 | 效果是否随训练改善，而不是盲目增加数据或步数 |
| P3 | 基础策略稳定后加事件/风险监测及自适应重规划 | 论文核心方法在可信基线上是否有增益 |

阶段门控可以作为工程辅助或规则对照，但若使用仿真物体真值，应明确标为oracle；不能混入未来可部署事件方法。
